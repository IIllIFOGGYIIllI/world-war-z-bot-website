Privacy & security

Clear boundaries for community data.

This page explains the live server connection, Discord sign-in, member data and protected Admin server controls. Last updated 4 August 2026.

Current status: the dashboard provides live public server and operational health information, secure Discord role verification, the signed-in member's own allowlisted survivor and economy summary, secure controlled player administration, audited Start, Stop and Restart controls, and protected server-action history for verified Admins and the Owner.

Current public website

The website is publicly hosted through GitHub Pages. It does not include analytics, advertising trackers or account cookies. The dashboard requests only public server status, player totals, capacity, map, platform and update time from the World War Z Bot API.

The custom Chernarus vector map and approved public POI list are hosted inside the website repository. No external map or tile service receives visitor requests. Live players, private bases, Admin positions and unpublished events are not included.

Other dashboard records remain fictional demonstrations. Links to Discord, GitHub or another service take you to that service, where its own privacy terms apply.

Discord sign-in

Discord OAuth identifies your account using only the basic identify permission. Railway then checks your current membership and roles in the World War Z Discord server. The website receives an opaque dashboard session, not the Discord access token, bot token or client secret.

Verified account information

  • Your Discord user identifier, username and display name.
  • Your current membership and assigned roles in the World War Z Discord server.
  • Your resulting member, Admin or owner dashboard access level.

Discord's temporary OAuth access token is revoked after the identity check and is never stored by the dashboard.

Access permissions

Visitors receive public information. Signed-in community members receive their own profile and economy summary, approved Admins receive protected player administration and Admin navigation, and the server owner receives owner access.

Railway fetches current guild membership and roles before authenticated information is returned and again before every protected player lookup, player action, history request or Start, Stop or Restart request. The protected endpoints accept only current Admin or Owner access; action routes also verify their target, confirmation and operation-specific safety requirements.

Security boundaries

  • Discord bot tokens, Discord client secrets and Nitrado API credentials remain on the Railway service.
  • The public API does not return online player names, credentials or private bot records.
  • The personal endpoint derives identity from the dashboard session; the browser cannot request another member ID.
  • The personal endpoint excludes warnings, Admin notes, raw Discord IDs and transaction counterparties.
  • Protected player administration exposes only allowlisted identity, activity, PvP, economy, staff-note, warning, ban and audit fields needed by current Admins.
  • Raw Discord IDs, DayZ UIDs, positions, evidence metadata, credentials and unrelated player records remain excluded from player administration.
  • Active warning case references and private-note references are returned only to verified Admins because they are required for the selected edit/remove control; staff display names may appear in protected notes and audit history.
  • Protected action history excludes Discord IDs, request IDs, recovery snapshots, database paths and raw Nitrado messages.
  • Admin navigation is hidden unless the correct role is verified, while backend authorization remains the real security boundary.
  • Every player write action requires a reason, an explicit confirmation dialog showing the selected PlayStation ID, fresh Admin/Owner authorization, target protection, one server-side action lock and permanent audit logging. The website sends the selected PSN internally so the Admin does not need to retype it.
  • Discord moderation also checks bot permissions and role hierarchy. Unlinking is Owner-only and writes a recovery snapshot before removing the active link.
  • Start, Stop and Restart require an explicit confirmation prompt, fresh Admin/Owner and state checks, shared duplicate protection and permanent audit logging.
  • The dashboard cannot edit configuration files.

Data handling and retention

OAuth state expires after 10 minutes and one-time login tickets after 2 minutes. The dashboard session is stored only in the current tab, disappears when the tab closes and expires on Railway after 12 hours. Railway stores hashes of these temporary values rather than their usable originals.

Profile, playtime, PvP and economy records already maintained by the Discord bot are read from its persistent database; visiting the dashboard creates no duplicate account copy. Server-control requests create an audit record containing the action, requesting Discord identity, source, optional reason, request identifier, server states, outcome and timestamps. Player administration reads and updates the existing Railway-controlled bot records without creating a public copy. Private notes, warnings, economy transactions, DayZ ban records and dashboard action audits follow the community's operational retention. Owner-only unlinking stores a recovery snapshot so an accidental unlink can be investigated or restored manually. Separate retention rules will be defined before ticket handling or evidence uploads connect.
