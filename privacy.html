Privacy & security

Clear boundaries for community data.

This page explains the live server connection, Discord sign-in and privacy rules for later account features. Last updated 3 August 2026.

Current websiteDiscord sign-inPermissionsSecurityData handlingContact
Current status: the dashboard provides live public server information and secure Discord identity and role verification. Private player records and protected controls are not connected.

Current public website

The website is publicly hosted through GitHub Pages. It does not include analytics, advertising trackers or account cookies. The dashboard requests only public server status, player totals, capacity, map, platform and update time from the World War Z Bot API.

Other dashboard records remain fictional demonstrations. Links to Discord, GitHub or another service take you to that service, where its own privacy terms apply.

Discord sign-in

Discord OAuth identifies your account using only the basic identify permission. Railway then checks your current membership and roles in the World War Z Discord server. The website receives an opaque dashboard session, not the Discord access token, bot token or client secret.

Verified account information

  • Your Discord user identifier, username and display name.
  • Your current membership and assigned roles in the World War Z Discord server.
  • Your resulting member, staff or owner dashboard access level.

Discord's temporary OAuth access token is revoked after the identity check and is never stored by the dashboard.

Access permissions

Visitors receive public information. Signed-in community members receive verified member access, approved staff receive staff access and the server owner receives owner access.

Railway fetches current guild membership and roles before authenticated identity information is returned. Private account and control endpoints will require separate protections before they are added.

Security boundaries

  • Discord bot tokens, Discord client secrets and Nitrado API credentials remain on the Railway service.
  • The public API does not return online player names, credentials or private bot records.
  • Secrets must never be committed to the public website repository or exposed to browser JavaScript.
  • Administrative actions require future authentication, permission checks, confirmation and an audit record.
  • The public dashboard cannot restart the server, edit balances, expose player records or change configuration files.

Data handling and retention

OAuth state expires after 10 minutes and one-time login tickets after 2 minutes. The dashboard session is stored only in the current tab, disappears when the tab closes and expires on Railway after 12 hours. Railway stores hashes of these temporary values rather than their usable originals.

Before private account features launch, separate retention rules will be defined for audit logs, tickets and moderation records. Community records already managed by the Discord bot remain subject to the bot's own administration processes.

Questions or requests

For questions about the World War Z community, your bot profile or future dashboard information, use the community's established Discord support ticket process.
